# ADR-014: 注释密度策略（≤5%）

日期：2026-09-12　状态：已实施

## 决策

代码注释密度以 **~5% 为上限**（维护者个人基线）。实施为一次机械化削减
（13.0% → 2.0%，字符串感知的注释剥离脚本 + 白名单）：

- 每文件保留两行 banner（`// iox — …` + 一行用途）。
- 保留**独立单行**的警示类注释（must/never/dangle/UB/生命周期/内核语义
  gotcha 等关键词且 ≤90 字符）；行尾注释同理。
- 多行注释块整块删除——决策性 rationale 全部已存档于 ADR-001~013，
  代码不再重复叙事。`/// ` 文档块同此处理。

## 理由

注释与 ADR 双轨重复维护必然漂移（本次削减前的 banner 已出现过 3 处与
文件名不符、8 处 `.cpp` 残留）。真源唯一化：**行为约束进测试，决策进
ADR，警示进单行注释**。实测落在 2.0%，低于 5% 上限；若需要更丰富的
就地文档，优先扩展 KEEP 白名单而非恢复长块。

## 验证

削减后全门禁重跑：release + ASan 各 115/115（616 断言）、63 头自含、
python 绑定（含 pip wheel 路径）端到端通过。
